# Basic Bindings

ftl's binding system is a small keyboard engine. This page covers the
concepts you need to read the binding tables; see
[Key Bindings](../key-bindings.md) for the complete reference.

## The leader key

The leader key (default: `BACKSLASH`, i.e. `\`) prefixes a family of
multi-key commands — for example `\fs` compresses the selection in a
`tar.bz2`. The leader is configured with:

```bash
ftl_cfg_leader_key='BACKSLASH'
```

The keyboard engine translates the current value of `ftl_cfg_leader_key`
into the symbolic token `LEADER` when looking up bindings. So a binding
registered as `"LEADER f c"` matches whatever you've configured as the
leader.

## Count prefix

A leading digit (or digits) becomes a count that some commands honor.
`3yy` tags three entries down; `5gt` jumps to tab 5. Counts are stored in
`ftl_kbd_count` and surfaced to commands as `ftl_kbd_has_count=1`. The
trie stores count-aware bindings under a `COUNT` prefix, so
`ftl::kbd::bind ftl tabs "COUNT gt" ftl::cmd::goto_tab` and
`ftl::kbd::bind ftl tabs gt ftl::cmd::next_tab` are distinct bindings.

## Multi-key sequences and the trie

Every binding is registered with `ftl::kbd::bind`:

```bash
ftl::kbd::bind <map> <section> "<keys>" <command_fn> "<help>"
```

`<keys>` is a space-separated list of tokens (e.g. `"LEADER f c"`,
`"g f f"`, `"CTL-W h"`). Internally these are concatenated into a single
key and stored in `ftl_kbd_trie`. When you press keys, the engine
accumulates them in `ftl_kbd_accumulated_keys` and looks up the trie. If
no match is found after a few keys (`ftl_kbd_keys_count > 3`) or after a
read timeout, the accumulation resets — exactly like vim's `timeoutlen`.

## Sub-modes

Some commands (incremental search `/`, the fzf-as-listen client) take over
the keyboard by setting `ftl_kbd_submode_handler` to a function. While a
sub-mode handler is set, every key is dispatched to it directly, bypassing
the trie. `ESCAPE` exits a sub-mode.

## The redo key

`ftl_cfg_redo_key` (default `.`) repeats the last non-movement command.
Movement commands (`move_*`, `cursor_*`) are excluded from redo via
`ftl::kbd::exclude_from_redo`. You can exclude your own commands too:

```bash
ftl::kbd::exclude_from_redo "my_dangerous_command"
```

## Viewing bindings

Press `c` to open the binding list. By default it appears in a tmux popup
(`ftl_cfg_bindings_in_popup=1`); set that to `0` for a fullscreen fzf.
The table is generated by `_ftl::kbd::generate_bindings_table` and
shows the map, section, key (with AltGr annotations), the command function,
and a short help string — all fzf-filterable.

## Reserved keys

The characters `å` and `Ä` are reserved for ftl's internal tmux-signal
IPC (`ftl::ipc::handle_pane_focus` and `ftl::ipc::handle_preview_request`).
Do not bind them.
